I want to understand how technology works — and learn how to build things of my own.

02 / The story behind the code

Every project starts somewhere.

This is not a story about knowing everything. It is a story about curiosity, learning unfamiliar tools and continuing to build.

01

Curiosity before confidence

Every developer begins with things they do not yet understand. For me, technology became an opportunity to explore how applications and websites are put together. The more I learned, the more I wanted to understand what happens behind the screen.

Instead of treating programming as something that could only be understood by experts, I began exploring the tools available to me and learning one concept at a time.

02

From learning to making

Learning became more interesting when I started applying concepts to my own projects. A line of code was no longer just something on a screen. It could change a layout, make a button work or help an interface respond to a user's action.

I explored web development and application development, learning to think about both the appearance of a product and the logic that makes its features work.

03

An idea that made me think bigger

My interest in building projects grew further when my English teacher suggested that I look into Coolest Projects. I did not end up participating, but the suggestion stayed with me.

It encouraged me to think about technology as more than a school exercise. Projects could become a way to express ideas, solve problems, practise communication and learn through creating something of my own.

04

Learning through real project challenges

Building a project is different from imagining one. Layouts need to work on different screens. Links must lead somewhere useful. Data needs to be handled carefully, and features require testing before they can be described as functional.

Projects such as Smart Academy and Smart Car Hub have given me opportunities to explore different parts of development. Not every feature is complete, and that is part of the learning process I want to document honestly.

05

The journey is still being written

My portfolio is more than a collection of project links. It is a record of what I am exploring, what I have attempted to build and what I hope to improve next.

I want to keep learning, become more confident with my tools, improve the quality of my work and develop projects that are useful beyond their first prototype.

06 / How I approach projects

Build with intention.

The principles I want to bring into every project as I improve my technical skills and learn to create better digital experiences.

01 / CURIOSITY

Keep exploring

Ask questions, try unfamiliar tools and understand why something works instead of simply copying the result.

02 / FUNCTION

Make it useful

Think beyond appearance. A good interface should help people understand what they can do and how to do it.

03 / IMPROVEMENT

Learn from every version

Test, identify problems, improve the implementation and be honest about what still needs work.

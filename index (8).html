01 / About me

I want to understand how technology works — and learn how to build things of my own.

My name is Mohamad Norizkandar bin Mohamad Faizal. I am interested in technology, programming and creating digital experiences. I enjoy exploring how an idea can develop into a website, application or prototype that people can interact with.

My development journey has involved learning JavaScript, experimenting with HTML and CSS, exploring React Native and Expo, and working with services such as Supabase. Each technology gives me another way to understand how digital products are created.

I am still learning. Some projects are prototypes, some are experiments, and others are ongoing development work. I believe being honest about what works, what remains unfinished and what I have learned is part of becoming a better developer.

02 / The story behind the code

Every project starts somewhere.

This is not a story about knowing everything. It is a story about curiosity, learning unfamiliar tools and continuing to build.

01

Curiosity before confidence

Every developer begins with things they do not yet understand. Technology became an opportunity to explore how applications and websites are put together. The more I learned, the more I wanted to understand what happens behind the screen.

Instead of treating programming as something only experts can understand, I began exploring available tools and learning one concept at a time.

02

From learning to making

Learning became more interesting when I started applying concepts to my own projects. A line of code was no longer just something on a screen. It could change a layout, make a button work or help an interface respond to a user's action.

I explored web and application development, learning to think about both a product's appearance and the logic that makes its features work.

03

An idea that made me think bigger

My interest in building projects grew when my English teacher suggested that I look into Coolest Projects. I did not end up participating, but the suggestion stayed with me.

It encouraged me to think about technology as more than a school exercise. Projects could become a way to express ideas, solve problems, practise communication and learn by creating something of my own.

04

Learning through real project challenges

Building a project is different from imagining one. Layouts need to work on different screens. Links must lead somewhere useful. Data needs to be handled carefully, and features require testing before they can be described as functional.

Projects such as Smart Academy and Smart Car Hub have given me opportunities to explore different parts of development. Not every feature is complete, and that is part of the learning process I want to document honestly.

05

The journey is still being written

My portfolio is more than a collection of project links. It is a record of what I am exploring, what I have attempted to build and what I hope to improve next.

I want to keep learning, become more confident with my tools, improve the quality of my work and develop projects that are useful beyond their first prototype.

Tech Glossary

Short definitions for terms you may encounter while developing projects.

API

An interface that allows software systems to request or exchange information in an agreed format.

Backend

The server-side part of an application that may handle data, authentication and business logic.

Frontend

The part of a website or app that people see and interact with directly.

Responsive design

A design approach that adapts layouts to different screen sizes and input methods.

Repository

A place where project files and version history are managed, often using Git.

Prototype

An early version used to explore an idea or test a concept; it is not automatically production-ready.

Deployment

The process of making a software project available in its intended environment.

Accessibility

Designing and building so people with different abilities can use a product.
